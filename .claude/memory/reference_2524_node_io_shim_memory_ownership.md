#2524 Phase 1 (`--node-io-shim`, PR #1791) factors `process` stream IO into a
separately-compiled linkable shim. Key facts for follow-ups:

- **Memory ownership (resolved):** the SHIM owns + exports the linear memory; the
  USER module IMPORTS it (memory index 0) plus `stdin_read`/`stdout_write`/
  `stderr_write`. Instantiate shim first (it imports only `wasi_snapshot_preview1`),
  then user with `{memory + io fns}` from shim — no instantiation cycle. Both Node
  (V8) and `wasmtime --preload js2wasm:node-io=node-shim.wasm` link cleanly.
- **New `ImportDesc` variant** `{ kind: "memory"; min; max? }` — encode kind byte
  `0x02` in `src/emit/binary.ts` (+ WAT in `src/emit/wat.ts`, + validator
  `numMemories` must add imported memories). Memory imports do NOT touch the func
  index space; only func imports increment `ctx.numImportFuncs`.
- **Strict gate:** `js2wasm:node-io` is in `ALWAYS_ALLOWED_IMPORT_MODULES`
  (host-import-allowlist.ts) — it's a canonical linkable Wasm interface, NOT a
  JS-host binding (like `wasi_snapshot_preview1`). Without this the strict
  `--no-host-imports`/WASI gate DROPS the import → stale funcMap idx → broken binary.
- **Codegen redirect points** (all gated on `ctx.nodeIoShim`, WASI-only): the
  console/string/Uint8Array/ArrayBuffer write helpers in `src/codegen/index.ts`
  (extracted `emitWasiWriteTail`), the GC stdin-read in
  `node-process-api.ts:emitProcessStdinRead`, and the linear zero-copy
  `tryEmitLinearU8StdWrite`/`tryEmitLinearU8StdinRead` in `linear-uint8-codegen.ts`.
  All keep their GC→linear staging copy and just call the imported `(ptr,len)` fn
  instead of building an iovec + `fd_*`.
- **Shim source:** `examples/native-messaging/node-shim.wat` (committed);
  `node-shim.wasm` is generated by `scripts/build-node-io-shim.mjs`
  (`buildNodeIoShim()` exported for tests) and gitignored.
- Phase 2 GC runtime boundary = #2514 (needs canonical rec group); Component
  Model packaging = #2525 (deferred).
