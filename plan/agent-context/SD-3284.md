# SD-3284 context summary (2026-07-15, session end)

## #3284 — compiler compat with unmodified test262 harness

Both root causes traced; issue's original hypotheses were wrong, corrected diagnosis banked on `main`.

**RC1 — `assert.sameValue(...)` "is not a function"**: NOT call-target type inference (the
issue's original hypothesis). Real cause: top-level code runs in wasm `(start)`, which executes
*during* `WebAssembly.instantiate`, before the host wires `setExports` — so host closure-wrap/
dispatch glue can't invoke the function value yet. Confirmed via: identical code inside a
post-`setExports` `export function test(){}` works; standalone mode dispatches natively and is
unaffected (the reference implementation for the real fix).

- Landed as knowledge PR **#3102 (MERGED)** — full `## Diagnosis` in
  `plan/issues/3284-compiler-compatibility-with-original-test262-harness.md`, three fix options:
  - **A — native host-mode dispatch** (the intended fix; next-window big-rock, `horizon: xl`)
  - B — rejected (breaks the raw-`(start)` external harness, e.g. test262.fyi)
  - C — speculative, not pursued
  - Plus a `describe.skip` invariant test marking the gap.
- Issue re-scoped `horizon: xl`, `status: ready` — unstarted, needs a fresh dev/senior-dev to pick
  up option A next window.

**RC2 — top-level `Promise.then` callback never fires**: `.then` lowers to `__make_callback`
(a `callback_maker`). The microtask drains while the async instantiate helper is still awaiting
`WebAssembly.instantiate` — after `(start)` but before `setExports` — so exports are undefined at
fire time and the callback silently no-ops.

- **Fixed in PR #3103**: ~20-line additive `deferToExports` park-and-replay in the
  `callback_maker` bridge, `src/runtime.ts` (~line 13411), mirroring the existing #2128 setter
  fix. Purely additive — post-`setExports` callbacks (every harness-executed body) skip the new
  branch.
- Validated: RC2 repro prints `in then, v= 42`; top-level `async fn().then()` fires; 83
  async/promise equivalence tests green locally; CI confirmed no regression (equivalence shards +
  cheap gate + merge shard reports all green).
- **Blocked only on a routine LOC-budget gate** (`src/runtime.ts` +20 over cap) — growth is
  genuinely intended, fix is a sanctioned `loc-budget-allow:` entry in this issue's frontmatter.
  Delegated to **shepherd-sonnet**, who owns the fix + push + enqueue end-to-end (SD-3284's
  worktree isolation was removed mid-session, hard-blocking its own Bash tool — no git access for
  the rest of the session).
