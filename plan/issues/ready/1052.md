# #1052 — Array destructuring ignores user-overridden Array.prototype[Symbol.iterator]

## Problem

Tests override `Array.prototype[Symbol.iterator]` and expect array destructuring to invoke the user-installed iterator. Our dstr lowering always calls the built-in array iterator directly, ignoring prototype overrides.

## Evidence from harvest

- **Test count:** 80 tests currently failing with this pattern
- **Top path buckets:**
  - `24 test/language/expressions/class/dstr/*`
  - `24 test/language/statements/class/dstr/*`
  - `6 test/language/expressions/object/dstr/*`
- **Top error messages:**
  - 12× `TypeError (null/undefined access): Array destructuring uses overriden Array.prototype[Symbol.iterator]`
- **Sample test files:**
  - `test/language/expressions/arrow-function/dstr/dflt-ary-ptrn-elem-id-iter-val-array-prototype.js`
  - `test/language/expressions/async-generator/dstr/named-dflt-ary-ptrn-elem-id-iter-val-array-prototype.js`
  - `test/language/expressions/class/dstr/private-gen-meth-static-ary-ptrn-elem-id-iter-val-array-prototype.js`

## Root cause hypothesis

Array-pattern dstr is compiled as a direct index-loop over the underlying array struct (fast path) and never checks whether `Array.prototype[Symbol.iterator]` has been replaced. The spec requires `GetIterator(value)` which goes through the prototype chain.

## Fix

When the dstr source type is `any`/externref or when we cannot prove `Array.prototype[Symbol.iterator]` has not been replaced, fall back to the generic iterator protocol. Alternatively, gate the fast path on a single dirty flag tracking replacement of built-in iterator methods.

## Expected impact

## Implementation Plan (dev-1047, 2026-04-11)

### Actual fast-path location

The array-pattern fast path is `compileExternrefArrayDestructuringDecl` in
`src/codegen/statements/destructuring.ts:829`. It emits:

```
for i in 0..n: __extern_get(tmpLocal, box(i)) → elem_i
```

i.e. numeric-index access on the RHS. This completely bypasses the iterator
protocol. Called from ~15 sites (variables, loops, closures, nested patterns).

### Approach

Switch `compileExternrefArrayDestructuringDecl` from "indexed access" to
"iterator protocol", unconditionally for externref RHS:

```
it = __get_iterator(rhs)          // host helper: calls rhs[Symbol.iterator]()
for element in pattern.elements:
  if rest: rest = __iterator_to_array(it)        // collect remaining
  else:    elem = __iterator_next_value(it)      // next().value or undefined
  ...apply default, destructure, etc.
```

Three new host imports (all thin wrappers, no runtime redesign):

1. `__get_iterator(externref): externref` — `Symbol.iterator`-aware iterator
   handle. Host implementation: `obj[Symbol.iterator]()`. Already called by
   our for-of implementation, so we can reuse `__extern_iterator_get` if it
   exists.
2. `__iterator_next_value(externref): externref` — returns `.next().value` or
   the sentinel for done (host returns `undefined` = wasm null).
3. `__iterator_to_array(externref): externref` — drains the iterator into
   a JS Array (for the rest element).

### Dual-mode compliance

These are host imports (JS host mode). Standalone mode fallback: the compiler
can emit a Wasm-native iterator loop using the existing `__struct_field_names`
path for vec wrappers, but that's #1052-followup scope. For this issue we
land the host-mode path first and note the standalone gap.

### Risk analysis

- **Performance**: swapping indexed access for iterator protocol is slower.
  Mitigation: add a compile-time `isPristineArrayLiteralRhs` check — if the
  RHS is an array literal (`const [x,y] = [1,2]` where `[1,2]` is created at
  this site), we know its `Symbol.iterator` is pristine and can keep the
  indexed path. This saves the fast common case.
- **Null/undefined mix with #1021**: dev-929's default-value guards use
  `__extern_is_undefined`. The iterator-protocol path returns `undefined`
  for exhausted iterators, which is what #1021 expects. Compatible.
- **Rest-element interaction**: `__iterator_to_array` must preserve rest
  semantics (rest is real `Array`, observable to `instanceof`).
