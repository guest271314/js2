# #1066 — Promise `constructor` lookup regression from #1047 allowlist

## Problem

After PR #93 (#1047 prototype-leak fix) merged, the test
`test/built-ins/Promise/prototype/then/ctor-access-count.js` regressed from
pass → fail with:

```
L46:3 The .constructor property is not an object
```

The test defines a `constructor` getter via `Object.defineProperty` on a
Promise instance and expects `prms.then(...)` to call it exactly once as part
of `SpeciesConstructor`. Our implementation is now returning a non-object
value from the `constructor` lookup, causing the SpeciesConstructor step 5
TypeError branch to fire.

## Suspected root cause

The #1047 fix filters prototype member visibility through a WeakMap allowlist
populated by `__register_prototype(proto, csv)`. The allowlist likely does not
include `constructor` (which isn't a user-declared method), so the
host-visible `get` trap on the prototype returns `undefined` rather than the
instance's shadowing `constructor` getter. The `Object.defineProperty` path
should still be respected — this is an instance-level descriptor, not a
prototype one — so the bug is probably that the Proxy `has`/`get` trap
short-circuits to the allowlist before consulting the instance's own
descriptors.

## Reproducer

```js
const p = new Promise(r => r());
let count = 0;
Object.defineProperty(p, 'constructor', {
  get() { count++; return Promise; }
});
p.then(() => {
  assert.sameValue(count, 1);
});
```

## Fix sketch

- In `_wrapForHost`'s `get` trap, check for own-property descriptors **before**
  falling through to the allowlist-filtered prototype lookup.
- Or: always include `constructor` in the implicit allowlist regardless of
  what `__register_prototype` was called with.
- Either fix is small, but needs a test that exercises both instance-shadowed
  `constructor` and plain prototype-inherited `constructor`.

## Acceptance criteria

- `Promise/prototype/then/ctor-access-count.js` passes
- No regression in the 179 tests that flipped green from PR #93
- The #1047 instance-field-leak guarantee still holds (instance fields do not
  appear on `C.prototype`)
