# Acorn differential corpus — gap map (#1712 umbrella)

Generated by `tests/dogfood/acorn-corpus.mjs` (run: `pnpm run dogfood:acorn-corpus`)
against **current main** (acorn@8.16.0 pinned, with #2837/#2838/#2325 landed),
2026-06-29.

The harness compiles the pinned acorn entry module **once**
(`skipSemanticDiagnostics: true`), instantiates it, `wrapExports`, then diffs
`parse(input)` for every corpus input against node-acorn (the **same** pinned
tarball = oracle, zero version skew) with `diffAst({ maxDivergences: 100000 })`
— **UNCAPPED** (the default cap of 8 hid real divergences twice in prior
sessions). Each divergence is classified **QUIRK** (cosmetic host-marshalling:
`sourceFile` extra field, booleans as i32 0/1) vs **REAL** (everything else).

## The THROW class is dominated by the `return` wall (#2838)

Bisection (`.tmp/probe-throws*.mjs`) localized the throws to a single
discriminator: **compiled-acorn throws a `WebAssembly.Exception` whenever it
parses a function body containing a `ReturnStatement`** (`return x;` AND bare
`return;` both throw). Confirmed structurally:

- `real/background.js` has **0** `return` statements → parses (REAL ×2 only).
- `real/edge.js` has **24** `return` statements → throws.
- `function f(){}` OK · `function f(){ foo(); }` OK · `function f(){ return 1; }` **THROWS**.

This is exactly **#2838** ("dynamic prototype-accessor dispatch … acorn `return`
wall", `status: in-progress`, owned by `sendev-2838`). **Not re-filed.** Two
_additional_ non-`return` throw walls were isolated and filed as **#2848**
(`new.target`, `yield <expr>`).

### Verified NOT present on current main

- **import/export spurious `attributes: []`** — the previously-suspected gap did
  **not** reproduce: `corpus/imports-exports.module.js` and
  `corpus/import-attributes.module.js` are `equal±quirks`. node-acorn emits the
  `attributes` field only at `ecmaVersion >= 2025`; the corpus runs **both**
  parsers at ev2025 (zero version skew), and compiled-acorn emits `attributes`
  exactly when node-acorn does — no spurious field. (The original observation was
  likely a version-skew artifact: compiled-acorn at one ecmaVersion vs an oracle
  at another.) No issue filed.

## Suspected shared root cause (marshalling family)

#2841 (`params[]`), #2844 (`quasis[]`), #2845 (`expressions[]`) are all
"node-typed **elements of a specific array property** come back without their
fields." They may share one `wrapExports` array-of-struct marshalling fix —
cross-referenced in each issue so a dev can consolidate.
